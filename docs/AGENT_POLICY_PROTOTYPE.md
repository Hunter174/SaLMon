# Game-side NPC policy prototype (issue #26)

**Status: not ready.** This is a standalone Godot example in `tests/godot/agent_policy.gd` and `agent_scheduler.gd`, not part of SaLMon's inference runtime or a real game's simulation. The interactive `semantic.gd` showcase now uses the policy filter, so an unverified favor, absent guards, or a non-existent combat event cannot be selected from its model options; it is still just a showcase, not a production game agent. It demonstrates a single shared model, authoritative action filtering and a measured fallback deadline. The actual game must supply trusted facts and increment each agent's revision whenever any policy-relevant fact changes; it must revalidate choices *again* just before committing effects. Player dialogue or the model must not create authoritative ledger, stock or authorization facts.

- `filter_actions(facts, actions, mandatory_ids)` checks explicit boolean/other fact requirements, action validity (`enabled`), and unreserved inventory (`inventory` minus `reserved`). Missing facts fail closed. Game-supplied mandatory action IDs handle urgent obligations. If no action is legal, return no action; if exactly one is legal, execute it without inference. The model only sees legal options.
- `agent_scheduler.gd` holds **one** model request in flight and at most two pending in the example; pending work has priorities and a wall-clock deadline measured from first submission. Overflow, timeout, invalid output and failures use a **game-provided legal safe fallback**. A stale revision never selects or applies an action. Same-revision cached model choices have a 256-entry cap; they are invalidated by the revision in the cache key. The model itself remains one shared loaded GGUF for every agent. `elapsed_ms` in the result of this scheduler measures submission-to-resolution, while the optional `queue_ms` and `service_ms` fields come from SaLMon completions. Godot frame/signal dispatch still affects the full time.
- Returning a fallback within 1 s does **not** mean that the model made a sub-second decision, or that the fallback was the desired narrative action. Bursts are throttled; the worker is not preempted by a later higher-priority request. Model scores remain conditional and uncalibrated.

## Reproduce locally

Run in the staged `tests/godot` project using **Godot 4.4.1**, which passes fresh local imports. These tests never ship weights inside the project/export:

```sh
Godot --headless --path tests/godot --script res://agent_policy_smoke.gd
SALMON_CHAT_MODEL=/absolute/path/to/Qwen3-0.6B-Q4_K_M.gguf \
  Godot --headless --path tests/godot --script res://agent_model_probe.gd
```

The fake backend smoke checks ledger/stock/authorization/urgency filtering, a no-action result, priority ordering, legal fallback and overflow, stale response, cache invalidation, invalid model output and cancellation/timeouts. One local run measured **0.009 ms p95** across 1,000 authoritative immediate decisions (a tiny isolated microbenchmark, not a game's frame-time guarantee).

The real-model probe uses eight *development* examples (four constrained, four discretionary). These are visible tests, **not held-out quality evidence**. With Qwen3-0.6B Q4 on this i7-10750H CPU, four generation threads, eight prompt threads and a **900 ms** deadline, all four discretionary decisions timed out (4/8 expected actions, no useful model-assisted decisions). An exploratory thread sweep on a different two-option *development* prompt over eight warm runs each found prompt-batch threads **2: median 919 ms/max 984 ms**, **4: 1509 ms**, **6: 1399 ms**, **8: 1376 ms**, **12: 1813 ms**. With two prompt threads and a 970 ms deadline, seven separate local real-model probe runs yielded only **2/7** full probe passes: four discretionary model responses in two runs; zero or three in the others (the remaining actions used fallbacks). All burst responses in those runs were under one second, but many were non-model fallbacks. A diagnostic 2 s deadline produced four correct model-assisted discretionary responses in one run at **794–853 ms**, while the eight-agent burst still had two results over one second. The probe deliberately exits nonzero when it cannot meet its strict toy-case quality+latency target; results vary with CPU load. All inference runs here used the CPU, with no GPU offload or GPU benchmarking. The small model's older broad paired-counterfactual benchmark was only **15/24** correct.

**Next gates:** agree on representative *actual game* state/action contracts and minimum quality + p95 latency budgets, freeze separate held-out pairs *before* tuning, measure repeat-run failure rate and rendered-game frame times, and test a task-adapted small model without training/evaluating on these visible fixtures. None of the current runs establishes consistent sub-second flexible decisions in actual gameplay. Keep issue #26 open.
